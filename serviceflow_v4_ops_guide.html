ServiceFlow V4
Operational Guide

Complete day-to-day reference for running the ServiceFlow credit retainer system — workflows, the Quarterly Order Form, email notifications, and monthly/quarterly checklists.

Version 4 · April 2026
QOF Phase 2 Live

§ 01What ServiceFlow Does

ServiceFlow manages credit-based retainer relationships with clients. Each client has a monthly credit allocation which they spend on services each quarter. All financial movement — credits loaded, services ordered, bonuses, refunds — flows through the Transactions ledger (Sheet 6). Everything else in the system feeds into or out of that ledger.

The system runs on Google Sheets (data), Google Apps Script (automation), and a custom HTML Quarterly Order Form embedded in the client portal for quarterly service selection.

The Three Work Types

Services agreed at the quarterly review, selected via the QOF, and scheduled for the coming months. Most predictable and preferred.
Clients select via the Quarterly Order Form
Credits reserved (not spent) until In Progress

Off Plan
Emergency / Priority
Urgent client requests outside the quarterly plan. Requires agency approval and pauses any scheduled ON PLAN work.

§ 02Key Rules to Always Remember
Rule 01
Credits deduct on "In Progress"
Not on Scheduled or Approved. Until In Progress, credits are only reserved — the balance hasn't actually moved.
Rule 02
Payment is never hybrid
Each request is 100% credits OR 100% cash. Two services needing different payment methods = two separate requests.
Rule 03
Emergency max = 2 months of credits
For a 150cr/month plan: max 300cr. Over this = cash payment or plan upgrade. No exceptions without a new contract.
Rule 04
7th is a soft cutoff
Requests after the 7th are flagged late but not blocked. You decide: approve, defer, or reject. Mark is_late_request = TRUE.
Rule 05
Interruptions never auto-resume
Emergency or break work pauses ON PLAN work to On Hold. It doesn't restart automatically — client must re-request at next review.
Rule 06
Breaks need 30 days notice
30-day minimum before the break month starts. You can override (document in break_history), but the rule applies unless overridden.
Rule 07
Parent records first
Clients → Contracts → Client_Plans → Transactions. Always create parent records before dependent rows. Dropdowns enforce this.
Rule 08
Don't edit Sheet 6 col G row 24+
Running balance is GAS-managed from row 24 onwards. To correct after a manual edit, run resetMarkers() — never type directly in those cells.
§ 03Credits & Balances
How Credits Work

Every financial movement for a client plan is a row in Sheet 6 (Transactions). The live balance is calculated by Sheet 1b (Client_Balances) col H — three SUMIF formulas netting all CREDIT rows (positive) and ORDER rows (negative). Col H is the authoritative figure used by GAS for form validation and is your go-to balance check.

Example Client Balance — April 2026
Monthly credits loaded Jan–Apr (4 × 150)+600
Q1 services ordered-350
Bonus credits (early adopter scheme)+400
Current balance — Sheet 1b col H+650

Transaction types that affect balance: CREDIT monthly allocation (positive), ORDER service debit (negative), BONUS extra credits (positive), and REFUND / ADJUSTMENT rows when applicable.

Monthly Credit Loading

On the 1st of each month, the GAS time-trigger function runMonthlyCreditLoad() adds a CREDIT row to Sheet 6 for each active client plan automatically. It includes a duplicate check — if a CREDIT row already exists for that client_plan_id + billing_period combination, it won't create another. Safe to re-run if the trigger fails.

Manual Credit LoadingIf you need to load credits manually (new client, trigger failure, mid-quarter onboarding), add a CREDIT row directly to Sheet 6: transaction_type = CREDIT, credits = +[monthly amount], billing_period = YYYY-MM (e.g. 2026-04), status = Completed. Use credit_pack_id format: cp[client_plan_id]_[month]_[year] e.g. cp1_4_2026.
Status & Credit Impact
StatusCredit ImpactNotes
ScheduledReserved — not deductedWork planned. Credits earmarked only.
ApprovedReserved — not deductedApproved and ready to start. Credits still reserved.
On HoldReserved — not deductedPaused by emergency work. Credits stay reserved.
In ProgressCredits deducted NOWWork actively being done. Balance moves at this moment.
CompletedAlready deductedWork delivered. Credits were deducted at In Progress.

ON PLAN — QOF-submitted (GAS writes as Approved; you move to In Progress when work starts):
Approved→In Progress→Completed
OFF PLAN — agency-entered emergency:
Pending→Approved→In Progress→Completed
Side paths:
Any reserved status→On Hold(emergency arrives)
Any reserved status→Cancelled(credits returned)
§ 04Agency Workflows
ON PLAN Work

ON PLAN work is selected by clients via the Quarterly Order Form and written automatically to Sheet 6 by GAS on submission. There should be no need to manually enter ON PLAN transactions for clients using the QOF. See § 06 Quarterly Order Form for the full process.

If you need to manually enter ON PLAN work (historical data, client without portal access): add rows directly to Sheet 6 with transaction_type = ORDER, work_type = ON_PLAN, status = Approved, submission_type = ADMIN.

Emergency / Priority Work
Workflow
OFF PLAN — Emergency or Priority Request
⌄
01
Client contacts you (email/call) with an urgent request outside their quarterly plan.
Note: what services they need, estimated credit cost, and whether it's before or after the 7th of the month.
02
You assess feasibility before agreeing anything.
Check Sheet 1b col H for their current balance. Emergency max = credits_per_month × 2. Check your capacity. If after 7th, flag as late request.
03
You enter in Sheet 10 (Requests):
work_type: OFF_PLAN_EMERGENCY or OFF_PLAN_PRIORITY · status: Approved (agency bypass) · submission_type: ADMIN
Then add rows to Sheet 10b (Request_Items) for each service.
04
You create Transaction rows in Sheet 6 for each approved service.
transaction_type: ORDER · credits: negative value (e.g. -200) · status: Approved · work_type: OFF_PLAN_EMERGENCY · billing_period: current month (e.g. 2026-04)
05
You pause ON PLAN work — find all Scheduled/Approved ON PLAN transactions for this client in Sheet 6. Change status → On Hold for each.
Filter Sheet 6: client_plan_id = this client + status = Approved or Scheduled + work_type = ON_PLAN. Change each to On Hold.
06
You email client confirming emergency is approved and that their scheduled work is paused until the emergency is complete.
07
You start work: change Transaction status Approved → In Progress. Credits are deducted at this moment.
08
You complete work: change status → Completed. Set completed_date. ON PLAN On Hold work can now be re-requested by the client.
Credit Limit ExceededIf the request exceeds 2 months of credits, present three options: (A) reduce scope to stay within the limit, (B) pay the full amount in cash — create a Purchased_Services entry (Sheet 13) not a Transaction row, (C) upgrade their retainer plan.
Revision Work
Workflow
Revision — Including Quarterly Borrowing
⌄
01
Client requests a correction or amendment. Check their current balance in Sheet 1b col H.
02
You assess options:
Credits available → proceed normally: Request in Sheet 10, Request_Item in Sheet 10b, Transaction in Sheet 6 with status: Approved.
Credits exhausted → offer quarterly borrowing (max 1 month's credits or £200) OR cash payment.
Check termination_notice_date in Client_Plans col AC — if set, quarterly borrowing is blocked.
03
You create the Transaction. If borrowing from next quarter: set billing_period to e.g. 2026-Q2 and add a note: "Borrowed from Q2: Revision ordered on [date]".
04
Start and complete work as normal. Revisions typically don't pause ON PLAN work unless they're substantial.
Partial Approval
Workflow
Client Submits Multiple Services — Only Some Can Be Approved
⌄
01
Client submits a multi-service request via email/call (Phase 2 — manual entry). Enter the Request header in Sheet 10 and all Request_Items in Sheet 10b.
02
You review each item for capacity and credits. For items you can't fulfil: set item_status → Rejected in Sheet 10b and add rejection_reason (e.g. "Insufficient capacity — suggest next month").
03
Set Request status → Partially Approved in Sheet 10. Create Transactions in Sheet 6 only for approved items.
04
Email client with a clear breakdown: what was approved, what was rejected and why, and how to re-request the rejected services next month.
Cash / Out-of-Pocket Payments
Workflow
Client Pays Cash — No Credits Involved
⌄
01
Determine cash payment is needed: credits exhausted, exceeds emergency limit, or client prefers to pay separately for a one-off.
02
You calculate the final price. Check their Bundles (Sheets 19/20) for any applicable retainer discount (typically up to 20%).
03
You create an entry in Sheet 13 (Purchased_Services) — NOT Transactions. Set payment_status = Pending.
Cash payments never touch the credit ledger. Credit balance is completely unaffected. Do not create a Transaction row for cash work.
04
Send invoice via FreeAgent. Do not start work until full payment is received. No partial payments accepted.
05
When payment arrives: update Purchased_Services — payment_status → Paid, add payment_reference (e.g. BANK-20260415-001) and payment_method.
Never HybridPayments are never mixed within a single request. If a client wants two services — one in credits and one in cash — these must be two completely separate requests.
Cancellations
Workflow
Client Requests Cancellation of Scheduled Work
⌄
01
Client contacts you requesting cancellation. Ask for a reason — required for the cancellation audit log.
02
You update the Transaction in Sheet 6:
cancellation_requested: TRUE · cancellation_request_date: today · cancellation_request_reason: their stated reason
03
You decide. If approved: change status → Cancelled. Set cancelled_by, cancelled_date, cancellation_reason. Credits are returned automatically via the Client_Balances SUMIF formula.
04
Email client confirming cancellation and the credits returned. Note they can now order different services with the freed credits.
Cannot Cancel In Progress WorkOnce status = In Progress, credits are deducted and work has started. Cancellation at this point requires a manual ADJUSTMENT or REFUND transaction and should be discussed case-by-case.
Retainer Breaks
Workflow
Client Requests a Retainer Break (Full Month Pause)
⌄
01
Client requests a break for a specific month. Check their Client_Plans row (Sheet 4):
break_eligibility_date (col X): must be in the past (6 months into plan)
breaks_used vs breaks_allowed_total (cols W, V): must have remaining breaks
Notice period: today's date must be 30+ days before break month 1st (or you override)
02
In Sheet 6, find all Scheduled transactions for the break month for this client. Change status → Cancelled. Set cancellation_reason: "Retainer break approved for [month YYYY-MM]".
03
Create a REFUND Transaction in Sheet 6:
transaction_type: REFUND · credits: +[credits_per_month] (positive value) · billing_period: break month · status: Completed
04
Update Client_Plans (Sheet 4): increment breaks_used (col W) by 1. Update break_history JSON (col AA) with break date, type (FULL_100), and amount.
05
Email client: confirm break approved, list all cancelled work, and clearly state that cancelled work must be re-requested for the following month — it does not auto-resume.
Late Notice OverrideIf the client gives fewer than 30 days notice, you can still approve it. Mark is_late_request = TRUE on break-related records and document your override decision in break_history JSON with a clear note.
Client Termination
Workflow
Client Gives Termination Notice
⌄
01
Client gives notice. Update Client_Plans: set termination_notice_date (col AC) = notice date. Set end_date (col J) = notice date + applicable notice period days.
02
From this point: no quarterly borrowing for revisions. All credits must come from the current period only. Block any Q-borrowing requests.
03
On end_date: change Client_Plans status → Inactive. Cancel all future Scheduled transactions. Set bundle_active → FALSE in Bundles_Plan_Join (Sheet 20) for all this client's bundles.
04
Link any uninvoiced Completed transactions to a final FreeAgent invoice. Send a final "Services Delivered" email summarising all work completed.
Plan Upgrades & Downgrades
Workflow
Client Upgrades or Downgrades Their Retainer Plan
⌄
01
New contract signed. Zapier creates a Contracts (Sheet 25) row automatically, or add manually if Zapier isn't configured.
02
You create a new Client_Plans row with the new credit amount, cost, and contract_id. Set is_plan_level_change = TRUE and previous_client_plan_id = the old plan's ID.
03
Update the old Client_Plans row: status → Inactive, end_date = changeover date.
04
Transfer bundles: use GAS custom menu ServiceFlow → Copy Bundles from Previous Plan. Script checks each bundle's minimum_plan_value_gbp and copies eligible ones. Review and manually add any newly unlocked bundles.
05
Email client confirming upgrade and listing any new bundles or perks they've unlocked.
Month-End Invoice Linking
Workflow
Linking FreeAgent Invoices to Completed Transactions
⌄
01
FreeAgent invoice created. Zapier auto-populates Sheet 17 (Invoices) with linked_status = Pending. No transactions linked yet.
02
Work progresses through the month. Transactions move through statuses. Any still In Progress or Scheduled at month end won't link this cycle — they carry to the next.
03
You run the month-end link: ServiceFlow → Link Invoice to Services from the Sheets custom menu. Select client, month, invoice number. Script finds all Completed transactions for that client/month and updates their invoice_id column.
04
Auto Sheet 17 updates: linked_status → Linked, transaction_count, linked_date = today. "Services Delivered" email auto-sent to client.
Completed Transactions OnlyOnly Completed transactions get linked. In Progress or Scheduled work does not link — it carries to next month's invoice run. Ensure all deliverable work is marked Completed before running the link script.
§ 05Late Request Handling

The 7th of each month is the standard order cutoff. Requests after this are flagged but not blocked — you decide what to do.

SituationAction
After 7th — genuine urgencyApprove at your discretion. Mark is_late_request = TRUE in Sheet 10 and record late_request_reason. Note approval for capacity tracking.
After 7th — not urgentDefer to the 1st of next month. Inform client politely. Don't enter the request yet — wait for next cycle.
Pattern of late requests from same clientRaise in the next quarterly review. Consider adjusting their QOF submission reminder or deadline_date in Sheet 30.
§ 06Quarterly Order Form (QOF)

The Quarterly Order Form is a custom HTML form embedded in the client portal as an iframe. Clients browse their available services for the quarter, select one service per month slot, and submit. On submission, GAS automatically writes ORDER rows to Sheet 6 and bonus rows to Sheet 31 — no manual data entry needed.

Setting Up a New Quarter

All QOF configuration lives in Sheets 26–30. Enter the data here and the form URL generates automatically in Sheet 30 col L.

①
Add the Quarter — Sheet 26 (Quarters)
Add a row: q_name (e.g. Q3 2026), q_number (3), q_year (2026). The q_months formula auto-derives. Use q_months_manual_override if it's a partial quarter (e.g. "5,6" for a 2-month start).
②
Build the Service Pool — Sheet 27 (Q_Options)
Add one row per service to offer. Set: client_plan_id (FK), q_id (FK → new Quarter row), service_id (FK), bonus_credits (0 if no bonus). All rows with the same q_opt_id form one pool. Set dependency_override (col L) = TRUE to bypass pre-req checks for specific services.
③
Add Strategies (Optional) — Sheets 28 & 29
To show named strategy recommendations (e.g. "Strategy A: Google Ads Focus"), add strategy rows to Sheet 28 (Q_Options_Strat) with a client_ref (A, B, C), name, description, focus, and not_focus. Then pin services + recommended months to each strategy in Sheet 29 (Q_Options_Strat_Services).
④
Generate the URL — Sheet 30 (Q_Order_Links)
Add a row: q_opt_id, q_id, quarter_ref (internal label, e.g. Q3 2026 – TRC Full), form_base_url. Set deadline_date (col M) — leave blank for the default of 7th of Month 1. Set expiry_date (col J) if needed. The full ready-to-paste URL auto-generates in col L. Copy it into the client portal iframe src attribute.
⑤
Confirm Formspark Webhook
Verify the Formspark webhook is pointing at the current live GAS endpoint. Only needs checking when a new GAS version has been deployed. Current live endpoint and HTML filename are documented in the handoff file.
⑥
Load Month 1 Credits (if manual)
If the monthly credit load hasn't yet fired for Month 1 of the new quarter, load manually in Sheet 6. Month 2 and 3 credits are loaded automatically by runMonthlyCreditLoad() on the 1st of each month.
Expiry vs Void — Sheet 30Use expiry_date (col J) for normal link expiry — the redirect chain to a replacement link (col K) is still followed. Use is_void = TRUE (col N) for a hard block — no redirect, the form shows an error immediately. Use is_void when you need to stop all access regardless of any redirect setup (e.g. major error, form sent to wrong client).

§ 07Email Notifications

GAS sends emails via MailApp (the Google account that owns the GAS script). The client email address is taken from Client_Plans col G (notification_email) — this is plan-specific and already in the GAS read chain, making it the preferred source.

All sent emails are logged in Sheet 8 (Email_Log) with email_type, recipient, sent_date, status (Sent/Failed/Skipped), and the trigger_event. Always check Sheet 8 first when a client says they didn't receive an email.

Per-Client Email Suppression — Client_Plans

Each client plan has four email suppression checkboxes in Sheet 4 (cols O–R). These let you switch off specific notification types per client without touching GAS code.

Col O
disable_order_emails
Suppresses the quarterly order confirmation email to the client after QOF submission.
Admin notification still sends
Col P
disable_reset_emails
Suppresses the monthly credit load notification sent on the 1st of each month.
Col Q
disable_reminder_emails
Suppresses order deadline reminder emails sent ahead of the 7th cutoff.
Col R
disable_delivery_emails
Suppresses service delivery confirmation emails when work is marked Completed.

The two supported quarterly order email scenarios:

Scenariodisable_order_emailsResult
Confirmation to admin AND client (default)FALSEClient receives order confirmation. Admin receives notification. Both send.
Confirmation to admin onlyTRUEClient email suppressed. Admin notification still sends.
Admin Submission vs Suppression Flag — Independent Controlsadmin=true URL param is session-level — suppresses client email for that one submission regardless of the flag setting. disable_order_emails (col O) is plan-level — suppresses client email on every submission for that client. Both can be active simultaneously.
§ 08Monthly Checklist
1st
Credit load — runMonthlyCreditLoad() fires automatically. Verify CREDIT rows appeared in Sheet 6 for all active client plans. Check Sheet 1b col H updated correctly.
1st–3rd
Capacity check — review your available capacity. Check Sheet 12 (Unavailability) for any agency holidays or reduced-capacity periods. Notify clients early if affected.
3rd
Reminder check — if it's the start of a new quarter, check whether clients have submitted their QOF. Consider sending a manual reminder if the deadline reminder email hasn't triggered.
7th
Order cutoff — soft deadline for new requests. After this, flag new requests as late and decide case-by-case. Review any outstanding pending requests and action them before capacity is committed.
Throughout
Status updates — as work starts, change Approved → In Progress (credits deduct at this point). As work is delivered, change In Progress → Completed. Set completed_date on completion. These drive the credit ledger and invoice linking.
Last day
Invoice linking — run ServiceFlow → Link Invoice to Services from the GAS custom menu. Link all Completed transactions for the month to the FreeAgent invoice. Verify linked_status = Linked in Sheet 17.
Full Monthly Checklist
  • Verify CREDIT rows loaded for all active plans in Sheet 6 (check billing_period matches current month)
  • Check Sheet 1b (Client_Balances) col H shows the correct balance for each client after credit load
  • Review any outstanding late requests from previous month and close or defer them
  • Update work statuses as services start (→ In Progress) and are delivered (→ Completed)
  • Action any pending cancellation requests from clients
  • Link month-end invoices to completed transactions (last working day of month)
  • Check Sheet 8 (Email_Log) for any Failed email sends — re-send manually if needed
  • Run ServiceFlow → View Uninvoiced Services to catch any completed work not yet linked to an invoice
§ 09Quarterly Checklist

Run through this at the start of each new quarter — typically before or just after the 1st of Month 1.

  • Add the new Quarter row to Sheet 26 (Quarters) with correct q_name, q_number, q_year, and months
  • Build the service pool for each active client in Sheet 27 (Q_Options) — one row per service offering, correct q_opt_id, q_id, service_id, bonus_credits
  • Add strategy groupings to Sheet 28 and service-month assignments to Sheet 29 (if using strategies this quarter)
  • Generate the form URL by adding a row to Sheet 30 (Q_Order_Links) — copy col L URL
  • Set deadline_date (col M in Sheet 30) for each link — or leave blank for the 7th-of-month default
  • Paste the URL into the client portal iframe src for each client
  • Verify the Formspark webhook is pointing at the current live GAS endpoint (check handoff doc for URL)
  • Confirm Month 1 credits have loaded (check Sheet 6 and Sheet 1b for CREDIT rows)
  • Send clients a heads-up that their Quarterly Order Form is ready to complete
  • Book quarterly review meetings to discuss the new quarter's ON PLAN work
  • Check for plan upgrades, bundle renewals, or any Client_Plans changes needed
  • Review break_eligibility_date (Client_Plans col X) for all clients — flag any who become break-eligible this quarter
  • Review next_review_date (Client_Plans col S) — ensure review meetings are scheduled for all active clients
  • Check Service_Promotions (Sheet 21) — any promos starting or ending this quarter that need setting up or closing off
§ 10New Client Setup Checklist

Follow this order strictly — child records require their parent records to exist first. Dropdowns enforce this but knowing the order saves confusion.

Step 1 — Client Record · Sheet 2 (Clients)
  • Add row: client_id (manual text e.g. NEWCO-2026), client_name, status = Active
  • Generate auth_key (16-char alphanumeric — the key used in all QOF URLs for this client)
  • Set auth_key_created = today, account_manager = your email, add any notes
Step 2 — Contract · Sheet 25 (Contracts)
  • Add row: contract_id (e.g. CONTRACT-2026-001), contract_name, contract_date, notes (e.g. "Signed via DocuSign")
  • If Zapier is configured to create contracts from FreeAgent/DocuSign, verify the row appeared automatically
Step 3 — Client Plan · Sheet 4 (Client_Plans)
  • Fill client_id (col B from dropdown) — client_plan_id auto-fills in col A
  • Enter plan_name, credits_per_month, default_cost_credits, cost_gbp_per_month
  • Enter notification_email (col G) — this is the address GAS sends all order confirmation emails to
  • Set status = Active, start_date, contract_id (dropdown → Sheet 25)
  • Set allow_overdraft and overdraft_limit if applicable to this plan
  • Set break_eligibility_date (col X) — typically 6 months from start_date
  • Set breaks_allowed_total (col V) — standard = 2
  • Set break_notice_period_days (col AB) — standard = 30
  • Set next_review_date (col S) and review_frequency_days (col U) — standard = 90 (quarterly)
  • Set all four disable_*_emails flags (cols O–R) — default = FALSE (all emails on)
Step 4 — Bundles · Sheets 19 & 20
  • Identify which bundles this client is entitled to (check their contract / plan tier)
  • Add rows to Sheet 20 (Bundles_Plan_Join): bundle_id (FK), client_plan_id (FK), bundle_active = TRUE, bundle_start_date = plan start_date, activation_notes
Step 5 — First Credit Load · Sheet 6 (Transactions)
  • Add a CREDIT row for Month 1: transaction_type = CREDIT, credits = +[credits_per_month], billing_period = YYYY-MM, status = Completed
  • Use credit_pack_id format: cp[client_plan_id]_[month]_[year] e.g. cp3_7_2026
  • Add a row in Sheet 1b (Client_Balances) for this client_plan_id — the formulas populate automatically once the row exists
  • Verify Sheet 1b col H shows the correct balance
Step 6 — Config Sheet (Balance Marker)
  • Add a row to the Config sheet for this new client plan: config_key = BALANCE_MARKER, client_plan_id = [new ID]
  • Set marker_row = the sheet row number of their first credit row in Sheet 6
  • Set marker_balance = the value in col G of that row (the running balance at that point)
  • From this point, GAS owns and updates the marker on every write
Step 7 — QOF Setup & Portal
  • Follow the quarterly setup steps (§ 09) to generate their first QOF URL for the current quarter
  • Paste URL into client portal iframe in Kitchen.co
  • Set up client's portal access in Kitchen.co and send welcome email
  • Book the first quarterly review meeting

§ 12Troubleshooting
ProblemLikely CauseFix
Client balance in Sheet 1b looks wrongA transaction row has incorrect credits value, wrong client_plan_id, or wrong transaction_type. The SUMIF picks up all matching rows.Filter Sheet 6 by client_plan_id. Review every row. Correct the bad value. Sheet 1b updates automatically.
Col G (running_balance) shows wrong values from row 24+A manual edit was made to a GAS-managed row, or rows were inserted above the Config marker without running resetMarkers().Run the GAS function resetMarkers() from the Apps Script editor. Never manually edit col G from row 24+ directly.
QOF form shows blank or error on loadURL params wrong (q_opt_id, month_range, auth_key), GAS endpoint URL outdated in the HTML file, or the Q_Order_Links row has is_void = TRUE or is past its expiry_date.Check Sheet 30 col L for the correct URL. Verify the HTML file has the current GAS endpoint URL (from handoff doc). Check is_void and expiry_date on the Q_Order_Links row.
QOF submission didn't write to Sheet 6Formspark webhook is pointing at an old/deprecated GAS endpoint. GAS doPost hit a runtime error. Formspark submission itself failed.Check Formspark dashboard for the submission attempt. Check GAS Executions log (Apps Script → Executions). Verify Formspark webhook URL matches current endpoint in handoff doc.
Client says they didn't receive a confirmation emaildisable_order_emails = TRUE in Client_Plans col O. notification_email (col G) is wrong or blank. GAS MailApp hit its 100/day quota. Email went to spam.Check Sheet 8 (Email_Log) for a row at the submission time. Check Client_Plans col G and col O. Ask client to check spam folder.
Dropdown in Sheet 6 shows no options / is emptyThe parent record doesn't exist yet (e.g. client_plan_id doesn't exist in Client_Plans).Create the parent record first. Order: Clients → Contracts → Client_Plans → Transactions.
Auto-increment ID formula not fillingFormula wasn't dragged far enough, or was accidentally overwritten. Or the trigger column (col B) is empty — the ID only fills when col B is not empty.Re-drag the formula from row 2 down to row 1000. Formula structure: =IF(B2<>"", MAX($A$1:A1)+1, "")
Sheet 31 col E (service_id) blank for new submissionsPreviously caused by missing CONFIG.SHEET.CONFIG in GAS. Fixed in GAS v3.2.0.Verify GAS is on v3.2.0 or later (check handoff doc). If still blank, check the GAS Executions log for runtime errors in doPost.
Invoice not linking to transactionsinvoice_month in Sheet 17 doesn't match billing_period format in Sheet 6. Or transactions aren't yet at Completed status.Check invoice_month format (YYYY-MM) matches billing_period in Sheet 6. Ensure all work for the month is Completed before running the link script — In Progress work won't link.
Col AJ or AL in Sheet 6 showing a date (e.g. 31/12/1899)The column was formatted as Date in Sheets. GAS writes these as String() to prevent it, but if the column format was changed manually it can revert.Select cols AJ and AL in Sheet 6. Format → Number → Plain text. This prevents Sheets from misinterpreting integer values as dates.
